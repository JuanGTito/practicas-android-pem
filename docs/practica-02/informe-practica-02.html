Gestión determinista de recursos

Las clases DatabaseConnection y UserSession implementan Closeable. El bloque use garantiza el cierre del recurso incluso si ocurre una excepción.

MainActivity.ktrecursos

    Log.d(TAG, database.query("SELECT * FROM users"))
}

UserSession("user_42").use {
    Log.d(TAG, it.obtainData())
}

3.8 LAMBDAS, OBJETOS ANÓNIMOS Y DATA CLASS

Lambdas y funciones de orden superior

Las lambdas se almacenan en variables, se asignan como eventos y se reciben como parámetros. Esto permite separar la operación de la lógica que decide cómo transformar, validar, filtrar o presentar datos.

MainActivity.ktlambdas
val greetingLambda: (String) -> String =
    { name -> "Hello, $name!" }
val duplicateLambda: (Int) -> Int = { it * 2 }

val buttonL = ButtonL("Send")
buttonL.onClick = {
    Log.d(TAG, "Sending form...")
    Log.d(TAG, "Validating data...")
}
buttonL.onValidate = { text -> text.length >= 3 }

También se utilizaron comparadores y listeners creados como objetos anónimos, además de una fun interface instanciada mediante SAM conversion.

4. RESULTADO DE LA PRÁCTICA

La rama practica-02 compila correctamente, genera un APK de depuración y supera todas las pruebas unitarias disponibles. La implementación demuestra el uso integrado de los principales mecanismos de programación orientada a objetos e idiomáticos de Kotlin.

Resultados verificados

  • Creación de objetos singleton, companion objects y objetos anónimos.
  • Modelado mediante clases, propiedades, métodos y diferentes tipos de constructores.
  • Encapsulamiento del estado con validación, getters, setters y field.
  • Funciones de nivel superior, extensiones, argumentos predeterminados y vararg.
  • Sobrecarga de métodos y operadores para vectores, matrices y comparaciones.
  • Herencia, sobrescritura, polimorfismo, clases abstractas e interfaces.
  • Composición y colaboración entre objetos con responsabilidades separadas.
  • Lambdas, funciones de orden superior, listeners y clases de datos.
  • Gestión segura de recursos mediante Closeable y use.

Conclusiones

1. Organización del códigoLa separación en clases pequeñas permite representar responsabilidades concretas y facilita la reutilización de comportamiento.
2. Seguridad del estadoEl encapsulamiento y la validación de propiedades evitan valores inválidos y reducen cambios accidentales desde otras clases.
3. FlexibilidadEl polimorfismo, las interfaces y la composición permiten sustituir implementaciones sin modificar a sus consumidores.
4. ConfiabilidadLas pruebas automáticas confirmaron los resultados de funciones, operadores, propiedades calculadas, polimorfismo y clases de datos.
